# 问答效果评估

本目录包含 12 道种子题，涉及国家奖学金和国家励志奖学金、例外条件、兼得限制、多轮指代、类别澄清、空输入和资料范围外问题。当前样本侧重奖学金，不能代表全部校园问答表现。

## 先检查题目与依据

在项目根目录运行：

```cmd
.\.venv\Scripts\python.exe -m evaluation.run_evaluation --check-only
```

不传参数时也只校验，不会调用模型。校验内容包括题目格式、唯一 ID、父级快照版本、原文存在性、章节和 PDF 页码是否一致，以及当前配置是否使用相同集合。不要求调用网络接口。

`questions.json` 中每题包括问题、历史上下文、预期状态、答案要点、依据原文与页码。`human_verified: false` 表示尚未人工对照原始 PDF 确认。当前依据来源是本地 OCR 父级快照，不是最新政策核查。人工核对要点及依据后再改为 `true`；OCR 存在错误时应先修复并重建对应资料版本。

## 运行真实问答

先小批量验证：

```cmd
.\.venv\Scripts\python.exe -m evaluation.run_evaluation --run --limit 3
```

运行全部题目：

```cmd
.\.venv\Scripts\python.exe -m evaluation.run_evaluation --run
```

`--run` 会实际调用当前问答流程，需要有效密钥和网络，可能产生接口费用。每题使用独立会话，并预先放入该题指定历史；题目之间不会互相污染历史。检索资源在一次运行中复用。程序只测试当前配置的完整流程，尚未提供纯向量/去重排等消融实验开关。

## 结果文件

每次运行在 `results/` 中创建独立目录，不覆盖旧结果：

- `questions.json`：本次题目与依据快照。
- `settings.json`：模型与检索参数及题集校验值，不保存密钥。
- `results.jsonl`：逐题原始回答、引用、状态、耗时和辅助指标；每题完成即写入。
- `summary.json`：状态匹配率、预设父级依据平均覆盖比例、错误数和平均总耗时。
- `review.csv`：供人工填写正确性、完整性、引用支持评分和备注。

中断时已完成题目的 JSONL 保留，汇总和 CSV 可能尚未生成；重新运行会产生新目录，不会自动续跑。首题可能包含资源初始化时间，因此不能把各题耗时直接看成稳定服务延迟。

## 指标怎么理解

- 状态匹配率：实际状态是否符合题目的预期状态。
- 预设依据覆盖比例：回答返回的来源中，包含多少预设父级 ID。它不是候选检索召回率，也不是答案正确率；存在其他等价依据时可能低估。
- 人工评分：在 `review.csv` 填写 0（不符合）、1（部分符合）、2（符合）。分别检查结论是否正确、条件与例外是否完整、引用原文是否支持回答。无引用的澄清/无效输入等题，引用支持列留空并注明“不适用”。

程序不会用关键词出现次数判断答案正确，也不会自动把人工评分汇总为正确率。CSV 的人工修改不会自动回写 JSONL。尚未人工核对的题集和少量题目结果只能用于开发检查，不宜直接当作正式论文结论。

## 扩展题集

复制已有题目结构并使用唯一 ID；事实问答必须提供依据。增加更多类型及困难问题，并尽量保留一部分未用于调试的独立测试题。

更新 PDF、父级快照或知识库集合后，需重新核对全部依据，再更新题集的集合名称与 `parents_sha256`；不能为了跳过校验只修改哈希。

结果中包含完整问题、回答及手册片段，分享前自行检查内容。本目录没有预填真实模型评估成绩。
